# Feature 4 — 도서 및 Shelf 관리 기능 정의

> 상태: Draft · 핵심 도메인 및 주요 비즈니스 정책 확정, 일부 세부 정책 미결정  
> 범위: 도서 탐색, 독서 상태 관리, Shelf 구성  
> 상위 문서: [MyShelf 서비스 기획 개요](./myshelf-product-overview.md)  
> 데이터 모델: [ERD](../database/erd.md)

## 1. 목표

MyShelf는 독서와 필사를 통해 개인의 취향을 아카이빙하는 서비스다.

Feature 4에서는 사용자가 관심 있는 책을 발견하고, 자신의 독서 상태를 관리하며, 여러 Shelf에 자유롭게 책을 구성하는 경험을 구현한다.

Shelf는 실제로 소유한 책을 보관하는 물리적인 책장이 아니라, **읽었거나 읽고 싶은 책을 자신의 기준으로 모으고 배치하는 디지털 보드**다.

이번 Feature의 목표는 다음과 같다.

- 외부 도서정보를 활용하여 책을 검색한다.
- 관심 있는 책을 특정 Shelf에 등록한다.
- 사용자별 독서 상태를 관리한다.
- 사용자가 여러 Shelf를 생성하고 자유롭게 구성한다.
- 동일한 책을 여러 Shelf에 배치할 수 있다.
- 다른 사용자의 도서 및 Shelf 데이터에 접근하지 못하도록 한다.

## 2. 기능 요구사항

### 2.1. 도서 탐색 및 조회

| 기능 | 설명 |
|---|---|
| 도서 검색 | 제목, 저자 등으로 외부 도서정보를 검색한다. |
| 도서 상세 조회 | 제목, 저자, 표지, 출판사, ISBN 등 제공 가능한 도서정보를 확인한다. |
| Shelf별 도서 조회 | 특정 Shelf에 배치된 책을 조회한다. |
| 전체 도서 조회 | 사용자의 모든 Shelf에 속한 책을 중복 없이 조회한다. |

도서정보는 외부 도서 API를 활용한다. 전자책 본문 등 도서 콘텐츠는 제공하지 않는다.

초기에는 외부 API에서 조회되며 ISBN이 존재하는 도서만 등록 대상으로 한다.

책을 별도의 개인 도서 목록에 먼저 등록하는 단계는 두지 않는다.

**특정 Shelf에 책을 추가하는 행위가 곧 사용자의 도서 등록이다.**

도서 검색 및 등록은 Shelf가 확정된 이후의 사용자 흐름에서 제공한다.

### 2.2. 독서 상태 관리

사용자별로 다음 세 가지 상태를 관리한다.

| 상태 | 의미 |
|---|---|
| `WANT_TO_READ` | 앞으로 읽고 싶은 책 |
| `READING` | 현재 읽고 있는 책 |
| `READ` | 완독한 책 |

- 사용자는 Shelf에 등록한 책의 독서 상태를 변경할 수 있다.
- 독서 상태는 개별 Shelf가 아닌 UserBook에 속한다.
- 같은 UserBook이 여러 Shelf에 존재하더라도 독서 상태는 동일하다.
- 독서 상태는 DB의 `reading_statuses` Lookup Table을 기준으로 관리한다.
- Java에서는 동일한 상태 코드를 Enum으로 표현한다.
- 실물 도서의 소장 여부는 관리하지 않는다.
- 페이지 단위 진행률이나 독서량은 관리하지 않는다.

최초 등록 시 독서 상태를 어떻게 지정할지와 상태 간 전환 정책은 별도로 결정한다.

### 2.3. Shelf 관리

Shelf는 사용자가 원하는 기준으로 책을 모으는 독립적인 보드다.

| 기능 | 설명 |
|---|---|
| Shelf 생성 | 새로운 Shelf를 생성한다. |
| Shelf 목록 조회 | 사용자가 생성한 Shelf 목록을 조회한다. |
| Shelf 단건 조회 | 특정 Shelf의 기본 정보를 조회한다. |
| Shelf 수정 | Shelf의 이름 등 기본 정보를 변경한다. |
| Shelf 삭제 | 더 이상 사용하지 않는 Shelf를 삭제한다. |
| 책 추가 | 특정 Shelf에 책을 추가한다. |
| 책 제거 | 특정 Shelf에서 책을 제거한다. |
| 책 순서 변경 | Shelf에 배치된 책의 순서를 사용자가 직접 변경한다. |

- 사용자는 여러 Shelf를 생성할 수 있다.
- 빈 Shelf를 허용한다.
- Shelf를 생성했다고 해서 책을 즉시 등록해야 하는 것은 아니다.
- Shelf의 소유자만 해당 Shelf를 관리할 수 있다.

## 3. 확정된 비즈니스 정책

### 3.1. Shelf 중심 도서 탐색 흐름

MyShelf에서는 **Shelf를 먼저 생성하거나 선택한 뒤 도서를 탐색하는 흐름**을 기본으로 한다.

사용자가 아직 어떤 Shelf도 가지고 있지 않다면 도서 탐색에 앞서 첫 Shelf를 생성해야 한다.

기본 흐름은 다음과 같다.

```text
MyShelf 진입
    │
    ▼
내 Shelf 목록 조회
    │
    ├── Shelf가 없는 경우
    │       └── 첫 Shelf 생성
    │
    └── Shelf가 있는 경우
            ├── 기존 Shelf 선택
            └── 새 Shelf 생성
    │
    ▼
대상 shelf_id 확정
    │
    ▼
Shelf 소유권 확인
    │
    ▼
도서 탐색 및 조회
    │
    ▼
선택한 Shelf에 도서 추가
```

**정책**

- Shelf가 하나도 없으면 먼저 Shelf를 생성하도록 안내한다.
- Shelf가 존재하면 기존 Shelf를 선택하거나 새로 생성할 수 있다.
- 도서 탐색 및 등록 흐름은 대상 `shelf_id`가 확정된 이후에 진입한다.
- 백엔드는 Shelf에 대한 접근 및 변경 시 해당 Shelf가 인증된 사용자의 소유인지 검증한다.
- 도서 등록은 선택된 Shelf를 대상으로 수행한다.
- 빈 Shelf는 정상적인 상태이며, 도서 등록을 강제하지 않는다.
- 외부 도서 API 검색 기능은 후속 구현 단계에서 개발한다.

Shelf 목록 조회와 Shelf 생성 자체에는 기존 `shelf_id`가 필요하지 않다.

전체 도서 목록은 별도의 논리적 조회 기능으로 유지하되, 사용자가 도서 탐색에 진입하는 흐름은 Shelf 중심으로 구성한다.

구체적인 API 경로와 요청 파라미터는 API 설계 단계에서 결정한다.

### 3.2. 도서 식별 및 중복 등록

MyShelf는 사용자별 도서 식별 기준으로 ISBN을 사용한다.

- 초기에는 ISBN이 있는 도서만 등록한다.
- 동일 사용자는 동일 ISBN을 가진 도서를 중복 등록할 수 없다.
- 서로 다른 사용자는 동일 ISBN의 도서를 각각 등록할 수 있다.
- 동일한 작품이라도 ISBN이 다르면 다른 판본으로 취급하고 별도 등록을 허용한다.
- ISBN은 저장 전에 일관된 형식으로 정규화한다.

데이터베이스에서는 `(user_id, isbn)` UNIQUE 제약으로 동일 사용자의 중복 등록을 방지한다.

같은 사용자가 이미 등록한 ISBN의 책을 다른 Shelf에 추가하는 경우, 새로운 UserBook을 생성하지 않고 기존 UserBook을 재사용한다.

도서정보의 원본은 외부 도서 API이며, MyShelf는 Shelf 표시 및 사용자별 관리를 위해 필요한 메타데이터를 저장한다.

별도의 공용 `books` 테이블은 두지 않는다.

### 3.3. 도서와 Shelf의 관계

- 하나의 UserBook은 여러 Shelf에 동시에 속할 수 있다.
- 하나의 Shelf에는 여러 UserBook을 배치할 수 있다.
- Shelf와 UserBook의 연결은 ShelfBook으로 관리한다.
- 동일 Shelf에 동일 UserBook을 중복 배치할 수 없다.
- 독서 상태는 UserBook에 저장되며 모든 Shelf에서 동일하게 적용된다.
- Shelf별 책의 배치 순서는 독립적으로 관리한다.
- 특정 Shelf에서 책을 제거해도 다른 Shelf의 동일 UserBook에는 영향을 주지 않는다.

현재 Shelf에 보관 중인 도서는 하나 이상의 ShelfBook 관계가 존재하는 UserBook을 의미한다.

반면 UserBook 자체는 과거에 등록했다가 모든 Shelf에서 제거한 책까지 보존할 수 있다.

### 3.4. 전체 도서 목록

전체 도서 목록은 **사용자의 모든 Shelf에 현재 속해 있는 책을 중복 없이 조회하는 논리적인 범위**다.

이를 위한 별도의 전체 도서 Shelf 엔티티는 생성하지 않는다.

- UserBook을 기준으로 중복 없이 조회한다.
- ShelfBook 관계가 하나 이상 존재하는 UserBook만 포함한다.
- 여러 Shelf에 같은 UserBook이 있어도 한 번만 표시한다.
- 모든 Shelf에서 제거된 UserBook은 전체 도서 목록에 표시하지 않는다.
- 외부 도서 검색 결과는 Shelf에 추가하기 전까지 전체 도서 목록에 포함되지 않는다.

### 3.5. 도서 제거 및 데이터 보존

사용자는 개별 Shelf에서 책을 제거할 수 있다.

- Shelf에서 책을 제거할 때 해당 ShelfBook 관계만 삭제한다.
- 다른 Shelf에 연결된 동일 UserBook은 영향을 받지 않는다.
- 마지막 ShelfBook이 제거되어도 UserBook은 삭제하지 않는다.
- UserBook의 독서 상태와 관련 기록은 유지한다.
- 마지막 Shelf에서 제거된 책은 전체 도서 목록에서 제외한다.
- MyShelf 전체에서 책을 일괄 삭제하는 별도 기능은 제공하지 않는다.
- UserBook에 대한 Soft Delete는 도입하지 않는다.

이를 통해 향후 문장 수집 및 필사 기록이 UserBook을 참조하더라도 Shelf 소속 변경과 관계없이 기록을 유지할 수 있다.

### 3.6. 사용자별 데이터 격리

- 사용자는 자신의 Shelf와 UserBook만 관리할 수 있다.
- 다른 사용자의 독서 상태, Shelf 구성 및 배치 순서를 조회하거나 변경할 수 없다.
- ShelfBook을 생성할 때 Shelf와 UserBook이 모두 인증된 사용자의 데이터인지 확인한다.
- Shelf와 UserBook의 `user_id` 일치 여부는 애플리케이션 계층에서 검증한다.
- DB에서는 FK와 UNIQUE 제약으로 기본적인 참조 무결성과 중복 방지를 보장한다.

다른 사용자의 데이터와 연결하는 요청은 허용하지 않는다.

## 4. 핵심 사용자 시나리오

1. 사용자가 로그인한 뒤 자신의 Shelf 목록을 확인한다.
2. Shelf가 하나도 없다면 첫 Shelf를 생성한다.
3. 기존 Shelf를 선택하거나 새로운 Shelf를 생성한다.
4. 선택한 Shelf를 기준으로 도서를 검색한다.
5. 관심 있는 책을 발견하면 해당 Shelf에 추가한다.
6. 이미 등록한 ISBN의 책이라면 기존 UserBook을 재사용한다.
7. 필요하다면 같은 책을 다른 Shelf에도 추가한다.
8. 각 Shelf 안에서 책의 순서를 원하는 대로 조정한다.
9. 책을 읽기 시작하거나 완독하면 독서 상태를 변경한다.
10. 독서 상태 변경은 해당 UserBook이 속한 모든 Shelf에 동일하게 반영된다.
11. 특정 Shelf에서 책을 제거해도 다른 Shelf에 배치된 동일한 책은 유지된다.
12. 모든 Shelf에서 제거한 책은 전체 도서 목록에서 제외되지만 UserBook 데이터는 보존된다.

위 시나리오는 대표적인 사용자 흐름이다. 최초 도서 등록 이후의 상태 변경, Shelf 이동 및 추가 배치는 사용자의 필요에 따라 자유롭게 진행할 수 있다.

단, 도서 탐색 및 등록에 앞서 대상 Shelf를 확정한다는 원칙은 유지한다.

## 5. 미결정 정책

다음 사항은 관련 기능 구현 전에 추가 논의한다.

| 주제 | 논의 사항 |
|---|---|
| 최초 독서 상태 | 최초 도서 등록 시 기본 상태를 지정할지, 사용자가 선택할지 |
| 상태 변경 | 독서 상태 간 이동을 자유롭게 허용할지 |
| 독서 날짜 | 독서 시작일·완독일을 기록할지 |
| Shelf 삭제 | Shelf 삭제 시 연결된 ShelfBook을 어떤 방식으로 처리할지 |
| 책 순서 변경 | `position`의 시작값, 중복 허용 여부, 순서 변경 방식 |
| 검색·정렬 | 검색, 필터, 정렬, 페이지네이션의 초기 범위 |
| ISBN 정규화 | 하이픈 제거, ISBN-10/13 등 입력 형식을 어떻게 통일할지 |
| 도서정보 | 외부 API에서 검색되지 않거나 ISBN이 없는 책의 향후 지원 여부 |

확정되지 않은 정책을 구현 편의에 따라 임의로 결정하지 않는다.

## 6. 구현 단계 및 완료 기준

Feature 4는 기능 전체를 한 번에 개발하지 않고, 작은 단위로 나누어 점진적으로 구현한다.

### 6.1. 첫 번째 구현 범위

첫 번째 단계에서는 Shelf의 기본 생성 및 조회 기능을 구현한다.

| 기능 | 범위 |
|---|---|
| Shelf 생성 | 인증된 사용자가 이름과 선택적 설명으로 Shelf 생성 |
| Shelf 단건 조회 | ID를 통해 자신의 Shelf 정보 조회 |
| Shelf 내 도서 목록 조회 | 특정 Shelf에 속한 UserBook 목록 조회 |

**완료 기준**

- 인증된 사용자가 자신의 Shelf를 생성할 수 있다.
- 생성한 Shelf의 ID를 이용하여 단건 조회할 수 있다.
- 빈 Shelf를 조회했을 때 정상적으로 빈 도서 목록을 반환한다.
- 해당 Shelf에 속한 도서 목록을 조회할 수 있다.
- 다른 사용자의 Shelf를 조회할 수 없다.
- 인증되지 않은 사용자는 보호된 Shelf 기능에 접근할 수 없다.
- 핵심 비즈니스 규칙을 테스트로 검증한다.

**이번 단계에서 제외**

- 외부 도서 API 검색
- Shelf에 책 추가 및 제거
- 독서 상태 변경
- Shelf 수정 및 삭제
- 책 순서 변경

도서 목록 조회의 정확한 응답 구조와 테스트 데이터 준비 방식은 API 및 테스트 설계 단계에서 결정한다.

### 6.2. Feature 4 전체 완료 기준

다음 사항을 구현 및 테스트로 검증할 수 있으면 Feature 4의 핵심 기능이 완료된 것으로 판단한다.

- 사용자가 Shelf를 먼저 생성하거나 선택한 뒤 도서를 탐색할 수 있다.
- 외부 도서정보를 검색하고 특정 Shelf에 책을 등록할 수 있다.
- 여러 Shelf를 생성·조회·수정·삭제할 수 있다.
- 동일 ISBN의 UserBook이 사용자별로 중복 생성되지 않는다.
- 동일한 UserBook을 여러 Shelf에 배치할 수 있다.
- 전체 도서 목록은 현재 Shelf에 속한 책을 중복 없이 보여준다.
- 등록한 도서의 정보 및 독서 상태를 조회·변경할 수 있다.
- 같은 책의 독서 상태 변경이 모든 Shelf에 동일하게 반영된다.
- Shelf별로 책의 배치 순서를 독립적으로 변경할 수 있다.
- 한 Shelf에서 책을 제거해도 다른 Shelf에 속한 동일한 책에는 영향을 주지 않는다.
- 마지막 Shelf에서 제거된 책은 전체 도서 목록에 나타나지 않지만 UserBook은 보존된다.
- 다른 사용자의 도서 및 Shelf 데이터에 접근하거나 이를 변경할 수 없다.
- 추가 합의한 도서 등록, Shelf 삭제, 상태 변경 정책을 테스트로 검증한다.

## 7. 이번 Feature의 제외 범위

다음 기능은 전체 서비스 기획에 포함되지만 Feature 4에서는 구현하지 않는다.

- 문장 수집 및 필사
- Paper 관리
- Collection 관리
- AI 도서 큐레이션
- 독서 진행률 및 상세 독서 통계
- Shelf 공개·공유 및 소셜 기능
- Redis·Kafka 등 별도 인프라를 활용한 고급 기능

후속 확장 가능성은 고려하되, 현재 요구사항에 필요하지 않은 구조를 선제적으로 도입하지 않는다.
