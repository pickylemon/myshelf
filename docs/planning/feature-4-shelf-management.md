## 1. 목표

MyShelf는 독서와 필사를 통해 개인의 취향을 아카이빙하는 서비스다.

Feature 4에서는 Shelf 생성·목록/상세 조회·수정·삭제와 사용자별 접근 통제를 구현한다. 도서 검색·등록, UserBook·ShelfBook 연결 및 독서 상태 관리는 Feature 5에서 다룬다.

이 문서는 초기 도서·Shelf 통합 기획도 포함한다. 아래 도서 관련 요구사항은 기획 배경으로 보존하며, 전체 구현 완료를 뜻하지 않는다. 등록·관리의 현재 계약은 [현행 정책](book-management-policy.md), Feature 5의 개발 결과는 [Feature 5 기록](feature-5-book-management.md), 조회 확장·사용자 지정 정렬은 [Feature 6](feature-6-book-browsing-and-ordering.md)에서 확인한다.

Shelf는 실제로 소유한 책을 보관하는 물리적인 책장이 아니라, **읽었거나 읽고 싶은 책을 자신의 기준으로 모으고 배치하는 디지털 보드**다.

Shelf와 후속 도서 관리 기능의 전체 목표는 다음과 같다.

- 외부 도서정보를 활용하여 책을 검색한다.
- 관심 있는 책을 특정 Shelf에 등록한다.
- 사용자별 독서 상태를 관리한다.
- 사용자가 여러 Shelf를 생성하고 자유롭게 구성한다.
- 동일한 책을 여러 Shelf에 배치할 수 있다.
- 다른 사용자의 도서 및 Shelf 데이터에 접근하지 못하도록 한다.

## 2. 기능 요구사항

### 2.1. 도서 탐색 및 조회

| 기능 | 설명 |
|---|---|
| 도서 검색 | 제목, 저자 등으로 외부 도서정보를 검색한다. |
| 도서 상세 조회 | 제목, 저자, 표지, 출판사, ISBN 등 제공 가능한 도서정보를 확인한다. |
| Shelf별 도서 조회 | 특정 Shelf에 배치된 책을 조회한다. |
| 전체 도서 조회 | 사용자의 모든 Shelf에 속한 책을 중복 없이 조회한다. |

도서정보는 외부 도서 API를 활용한다. 전자책 본문 등 도서 콘텐츠는 제공하지 않는다.

초기에는 외부 API에서 조회되며 ISBN이 존재하는 도서만 등록 대상으로 한다.

책을 별도의 개인 도서 목록에 먼저 등록하는 단계는 두지 않는다.

**특정 Shelf에 책을 추가하는 행위가 곧 사용자의 도서 등록이다.**

도서 검색 및 등록은 Shelf가 확정된 이후의 사용자 흐름에서 제공한다.

### 2.2. 독서 상태 관리

사용자별로 다음 세 가지 상태를 관리한다.

| 상태 | 의미 |
|---|---|
| `WANT_TO_READ` | 앞으로 읽고 싶은 책 |
| `READING` | 현재 읽고 있는 책 |
| `READ` | 완독한 책 |

- 사용자는 Shelf에 등록한 책의 독서 상태를 변경할 수 있다.
- 독서 상태는 개별 Shelf가 아닌 UserBook에 속한다.
- 같은 UserBook이 여러 Shelf에 존재하더라도 독서 상태는 동일하다.
- 독서 상태는 DB의 `reading_statuses` Lookup Table을 기준으로 관리한다.
- Java에서는 동일한 상태 코드를 Enum으로 표현한다.
- 실물 도서의 소장 여부는 관리하지 않는다.
- 페이지 단위 진행률이나 독서량은 관리하지 않는다.

Feature 5의 등록 API는 도서별 독서 상태를 필수로 받으며, 현재 상태 변경은 세 상태 사이의 전환을 별도로 제한하지 않는다. 화면 기본값 정책과 API 입력 계약은 [Feature 5의 독서 상태 정책](./feature-5-book-management.md#36-등록-시-독서-상태와-재등록-처리)을 참고한다.

### 2.3. Shelf 관리

Shelf는 사용자가 원하는 기준으로 책을 모으는 독립적인 보드다.

| 기능 | 설명 |
|---|---|
| Shelf 생성 | 새로운 Shelf를 생성한다. |
| Shelf 목록 조회 | 사용자가 생성한 Shelf 목록을 조회한다. |
| Shelf 단건 조회 | 특정 Shelf의 기본 정보를 조회한다. |
| Shelf 수정 | Shelf의 이름 등 기본 정보를 변경한다. |
| Shelf 삭제 | 더 이상 사용하지 않는 Shelf를 삭제한다. |
| 책 추가 | 특정 Shelf에 책을 추가한다. |
| 책 제거 | 특정 Shelf에서 책을 제거한다. |
| 책 순서 변경 | Shelf에 배치된 책의 순서를 사용자가 직접 변경한다. |

- 사용자는 여러 Shelf를 생성할 수 있다.
- 빈 Shelf를 허용한다.
- Shelf를 생성했다고 해서 책을 즉시 등록해야 하는 것은 아니다.
- Shelf의 소유자만 해당 Shelf를 관리할 수 있다.

## 3. 확정된 비즈니스 정책

### 3.1. Shelf 중심 도서 탐색 흐름

MyShelf에서는 **Shelf를 먼저 생성하거나 선택한 뒤 도서를 탐색하는 흐름**을 기본으로 한다.

사용자가 아직 어떤 Shelf도 가지고 있지 않다면 도서 탐색에 앞서 첫 Shelf를 생성해야 한다.

기본 흐름은 다음과 같다.

```text
MyShelf 진입
    │
    ▼
내 Shelf 목록 조회
    │
    ├── Shelf가 없는 경우
    │       └── 첫 Shelf 생성
    │
    └── Shelf가 있는 경우
            ├── 기존 Shelf 선택
            └── 새 Shelf 생성
    │
    ▼
대상 shelf_id 확정
    │
    ▼
Shelf 소유권 확인
    │
    ▼
도서 탐색 및 조회
    │
    ▼
선택한 Shelf에 도서 추가
```

**정책**

- Shelf가 하나도 없으면 먼저 Shelf를 생성하도록 안내한다.
- Shelf가 존재하면 기존 Shelf를 선택하거나 새로 생성할 수 있다.
- 도서 탐색 및 등록 흐름은 대상 `shelf_id`가 확정된 이후에 진입한다.
- 백엔드는 Shelf에 대한 접근 및 변경 시 해당 Shelf가 인증된 사용자의 소유인지 검증한다.
- 도서 등록은 선택된 Shelf를 대상으로 수행한다.
- 빈 Shelf는 정상적인 상태이며, 도서 등록을 강제하지 않는다.
- 외부 도서 API 검색 기능은 Feature 5에서 구현했다. 검색 API 자체는 대상 Shelf ID를 받지 않으며, 위 흐름은 화면의 사용자 시나리오다.

Shelf 목록 조회와 Shelf 생성 자체에는 기존 `shelf_id`가 필요하지 않다.

전체 도서 목록은 별도의 논리적 조회 기능으로 유지하되, 사용자가 도서 탐색에 진입하는 흐름은 Shelf 중심으로 구성한다.

구체적인 API 경로와 요청 파라미터는 API 설계 단계에서 결정한다.

### 3.2. 도서 식별 및 중복 등록

후속 개발에서 정리한 도서 식별·재사용·중복 처리의 당시 내용은 [Feature 5의 UserBook·ISBN 기록](./feature-5-book-management.md#32-userbook과-isbn)과 [동일 Shelf 중복 처리 기록](./feature-5-book-management.md#35-동일-shelf의-중복-등록-처리)을 참고한다. Shelf CRUD의 이름 중복 검사와 도서 등록의 중복 항목 제외는 다른 정책이다.

### 3.3. 도서와 Shelf의 관계

Shelf와 UserBook은 ShelfBook으로 연결되며 독서 상태는 UserBook, 서재별 메모·위치는 ShelfBook에 속한다. 관계의 보존·삭제·정렬 계약은 [Feature 5의 데이터 보존 정책](./feature-5-book-management.md#33-shelfbook과-데이터-보존)을 기준으로 한다.

### 3.4. 전체 도서 목록

현재 Shelf에 연결된 도서를 중복 없이 탐색하는 기능은 [Feature 6](./feature-6-book-browsing-and-ordering.md) 범위다. 별도의 전체 도서 Shelf를 만들지 않는 제품 방향은 [서비스 기획](./myshelf-product-overview.md#22-shelf--나만의-책장)을 참고한다.

### 3.5. 도서 제거 및 데이터 보존

Shelf 자체의 삭제는 Feature 4 기능이고, 연결된 도서의 보존 계약과 CASCADE 검증은 Feature 5에서 다룬다. [Feature 5의 데이터 보존 정책](./feature-5-book-management.md#33-shelfbook과-데이터-보존)을 따른다. 소프트 삭제를 별도로 두지 않은 판단 과정은 [학습 기록](../learning/database/soft-delete-and-source-of-truth.md)에 남긴다.

### 3.6. 사용자별 데이터 격리

본인의 Shelf만 생성·조회·수정·삭제할 수 있다. 미존재·타인 소유 Shelf는 구분하지 않고 404로 처리한다. 공통 접근·삭제 응답의 선택 근거는 [ADR-010](../decisions/010-private-resource-access-policy.md), 도서 연결 양쪽 소유권 계약은 [Feature 5](./feature-5-book-management.md#34-사용자별-접근-통제)를 따른다.

## 4. 핵심 사용자 시나리오

1. 사용자가 로그인한 뒤 자신의 Shelf 목록을 확인한다.
2. Shelf가 하나도 없다면 첫 Shelf를 생성한다.
3. 기존 Shelf를 선택하거나 새로운 Shelf를 생성한다.
4. 선택한 Shelf를 기준으로 도서를 검색한다.
5. 관심 있는 책을 발견하면 해당 Shelf에 추가한다.
6. 이미 등록한 ISBN의 책이라면 기존 UserBook을 재사용한다.
7. 필요하다면 같은 책을 다른 Shelf에도 추가한다.
8. 각 Shelf 안에서 책의 순서를 원하는 대로 조정한다.
9. 책을 읽기 시작하거나 완독하면 독서 상태를 변경한다.
10. 독서 상태 변경은 해당 UserBook이 속한 모든 Shelf에 동일하게 반영된다.
11. 특정 Shelf에서 책을 제거해도 다른 Shelf에 배치된 동일한 책은 유지된다.
12. 모든 Shelf에서 제거한 책은 전체 도서 목록에서 제외되지만 UserBook 데이터는 보존된다.

위 시나리오는 대표적인 사용자 흐름이다. 최초 도서 등록 이후의 상태 변경, Shelf 이동 및 추가 배치는 사용자의 필요에 따라 자유롭게 진행할 수 있다.

단, 도서 탐색 및 등록에 앞서 대상 Shelf를 확정한다는 원칙은 유지한다.

## 5. 후속 정책의 현재 상태

초기 기획에 대한 Feature 5 종료 시점의 후속 정리다. 아래 상태는 당시 기록으로 보존하며, 현재 규칙은 현행 정책 문서와 진행 중인 Feature 계획에서 확인한다.

| 주제 | 논의 사항 |
|---|---|
| 최초 독서 상태 | Feature 5에서 도서별 `readingStatus` 필수 입력 적용. 화면 기본값과 구분 |
| 상태 변경 | 현재 세 상태 사이 전환을 별도로 제한하지 않음 |
| 독서 날짜 | 독서 시작일·완독일을 기록할지 |
| Shelf 삭제 | V6의 CASCADE로 연결된 ShelfBook만 삭제하며 UserBook·다른 Shelf 연결 보존 |
| 책 순서 변경 | `position`의 시작값, 중복 허용 여부, 순서 변경 방식 |
| 검색·정렬 | 외부 검색·더 보기와 Shelf별 목록·기본 정렬은 구현. 조회 확장·사용자 지정 정렬은 Feature 6 |
| ISBN 정규화 | 당시 미적용. 향후 도입 시 현행 정책을 변경하고 이 기록은 보존 |
| 도서정보 | 외부 API에서 검색되지 않거나 ISBN이 없는 책의 향후 지원 여부 |

확정되지 않은 정책을 구현 편의에 따라 임의로 결정하지 않는다.

## 6. 구현 단계 및 완료 기준

Feature 4는 Shelf 자체의 CRUD에 집중하고, 도서 연결 기능은 Feature 5로 분리한다.

### 6.1. Feature 4 구현 범위와 현재 상태

다음 Shelf 기능의 운영 코드와 테스트를 구현했다.

| 기능 | 범위 |
|---|---|
| Shelf 생성 | 인증된 사용자가 이름과 선택적 설명으로 Shelf 생성 |
| Shelf 목록 조회 | 자신의 Shelf 목록 조회, 없으면 빈 배열 |
| Shelf 단건 조회 | ID를 통해 자신의 Shelf 정보 조회 |
| Shelf 수정 | 자신의 Shelf 이름·설명 변경, 기존 이름 유지 및 설명 null 허용 |
| Shelf 삭제 | 자신의 Shelf 삭제, 본문 없는 204 응답 |

**완료 기준**

- 인증된 사용자가 자신의 Shelf를 생성할 수 있다.
- 생성한 Shelf의 ID를 이용하여 단건 조회할 수 있다.
- 동일 사용자 내 이름 중복을 사전 검사와 DB UNIQUE 제약조건으로 방지한다.
- 다른 사용자의 Shelf 조회·수정·삭제와 미존재 요청을 동일한 404로 처리한다.
- 수정 실패 시 원본 유지, 생성 시각 유지·수정 시각 갱신 및 실제 삭제를 검증한다.
- 인증되지 않은 사용자는 보호된 Shelf 기능에 접근할 수 없다.
- 핵심 비즈니스 규칙을 테스트로 검증한다.

**이번 단계에서 제외**

- 외부 도서 API 검색
- Shelf에 책 추가 및 제거
- 독서 상태 변경
- Shelf 내 도서 목록 조회
- ShelfBook 연결 데이터가 있는 Shelf의 삭제 정책 및 검증
- 책 순서 변경

전체 테스트 통과와 최종 빌드·CI 통과는 구분한다. 최신 종료 상태는 [로드맵](roadmap.md)에서 관리한다.

### 6.2. 도서 기능의 후속 완료 기준

Shelf 생성·선택에서 이어지는 도서 시나리오의 완료 기준은 [Feature 5](./feature-5-book-management.md#63-feature-5-종료-기준)와 [Feature 6](./feature-6-book-browsing-and-ordering.md#4-완료-기준)에서 각각 관리한다. 해당 기능들의 체크리스트를 Feature 4에 중복 유지하거나 Shelf CRUD 종료 조건에 포함하지 않는다.

## 7. 이번 Feature의 제외 범위

다음 기능은 전체 서비스 기획에 포함되지만 Feature 4에서는 구현하지 않는다.

- 도서 검색·등록, UserBook·ShelfBook 연결 및 독서 상태 관리 (Feature 5)
- Shelf 내 도서 목록 조회 및 도서 연결 데이터의 삭제 정책·검증 (Feature 5)
- 전체 도서·상세 조회 및 책 순서 변경 (Feature 6)
- 문장 수집 및 필사 (Feature 7)
- Paper 관리
- Collection 관리
- AI 도서 큐레이션
- 독서 진행률 및 상세 독서 통계
- Shelf 공개·공유 및 소셜 기능
- Redis·Kafka 등 별도 인프라를 활용한 고급 기능

후속 확장 가능성은 고려하되, 현재 요구사항에 필요하지 않은 구조를 선제적으로 도입하지 않는다.

---

**현재 이후 범위:** Feature 4·5는 main에 병합했다. 포트폴리오 1차 정리와 운영 보완을 우선하고, 조회 확장·사용자 지정 정렬은 Feature 6에서 진행한다. 최신 진행 상태는 [로드맵](roadmap.md)을 참고한다.
