# Feature 6 — 도서 조회 확장 및 서재 정렬

> 상태: **예정** — Feature 5 병합·최초 배포 완료 후의 후속 기능. 포트폴리오 1차 정리와 운영 보완을 우선함
>
> 선행 기능: [Feature 5 — 도서 검색·등록 및 Shelf 연동](./feature-5-book-management.md)

## 1. 목표

Feature 5의 Shelf별 최소 도서 목록을 바탕으로 전체 도서 탐색·상세 조회와 사용자 지정 배치 순서를 추가한다. 이 기능들은 Feature 5 종료와 최초 배포의 필수 조건으로 두지 않는다.

## 2. 작업 범위

| 기능 | 요구사항 |
|---|---|
| 전체 도서 목록 | 하나 이상의 ShelfBook이 있는 본인 UserBook만 중복 없이 조회 |
| 등록 도서 상세 | 본인 도서의 메타데이터·독서 상태·소속 Shelf 조회. 메모는 서재별 데이터로 구분 |
| Shelf 내 순서 변경 | 같은 Shelf 안에서 배치 순서를 변경하고 다른 Shelf의 순서는 유지 |
| 외부 검색 응답 보완 | 현재 관리 중인 도서의 독서 상태 제공. 등록 Shelf는 현재 연결만 표시하며 UserBook 행의 존재 여부는 구분하지 않음 |

검색 필드 우선순위·외부 조회 크기 비교는 [Feature 5의 후속 실험](./feature-5-book-management.md#후속-구현실험--병합-우선순위와-외부-조회-크기)을 이어서 검토한다. 관련도 점수나 검색 구조 재설계를 필수 범위로 추가하지 않는다.

## 3. 구현 전 정할 계약

- 목록·상세 API 경로, 응답 필드와 페이징 방식
- 상세 조회에서 Shelf별 메모를 표현할 방법
- `position` 시작값, 재정렬 요청 범위와 중복·누락 위치 처리
- `position`이 null인 도서와 지정된 도서의 기본 노출 순서
- 외부 검색 응답의 독서 상태 표현. 현재 연결된 Shelf가 없는 책은 UserBook 존재 여부와 관계없이 동일하게 표시

현재 Shelf별 목록은 위치 지정 도서 우선·position 오름차순·수정 시각 내림차순·ID 내림차순으로 반환한다. 전체 도서 조회·사용자 지정 정렬 UseCase는 비어 있고, 이 문서의 신규 API와 처리는 아직 구현하지 않았다. 세부 계약은 구현 전에 정하고 테스트 기준으로 남긴다.

## 4. 완료 기준

- [ ] 전체 목록에 Shelf 연결이 있는 도서만 나타나며 중복되지 않는다.
- [ ] 상세 조회에서 메타데이터·공유 독서 상태·서재별 정보를 구분한다.
- [ ] 타인의 도서·Shelf 조회 및 순서 변경을 거부한다.
- [ ] 순서 변경은 해당 Shelf에만 반영되고 도서·메모·독서 상태를 보존한다.
- [ ] 검색 응답의 독서 상태와 현재 등록 Shelf가 관리 대상 도서의 상태와 일치하고, 연결 없는 UserBook의 과거 상태를 노출하지 않는다.
- [ ] 단위·웹·DB 통합 테스트 및 최신 빌드·CI를 확인한다.

UserBook 보존·중복 등록·메모 소유권 정책은 [Feature 5의 확정 정책](./feature-5-book-management.md#3-확정된-비즈니스-정책)을 따른다.
