# Feature 5 — 도서 검색·등록 및 Shelf 연동

> 이 문서는 Feature 5의 개발 범위·정책·검증 기록을 보존한다. 이후 정책 변경은 [현행 도서 관리 정책](book-management-policy.md)에 반영하며, 이 문서의 당시 정책을 소급 변경하지 않는다. 아래 설계 링크는 현재 구현을 확인하기 위한 안내다.

> 상태: **구현·테스트 완료, main 병합 (PR #25)** — 검색·등록·서재별 메모 수정·독서 상태 변경·ShelfBook 다건 삭제·Shelf별 목록 조회 검증 완료. 후속 작업으로 SSH 기반 EC2 CD와 기본 HTTP 배포 검증도 완료했으며, 전체 비즈니스 API의 운영 검증과는 구분함
>
> 범위: 외부 도서 탐색, UserBook 등록·독서 상태 변경, ShelfBook 연결·메모·삭제, Shelf별 도서 목록 조회
>
> 선행 기능: Feature 4 — Shelf CRUD

## 1. 목표

Feature 5에서는 사용자가 **자신의 Shelf에 도서를 추가하고, 여러 Shelf에서 같은 도서를 관리하며, 독서 상태를 기록**할 수 있도록 한다.

외부 도서 API는 메타데이터를 제공하는 수단이며, MyShelf가 관리하는 핵심 데이터는 **사용자별 도서(UserBook)**와 **Shelf 배치(ShelfBook)**다. Feature 4에서 확정한 Shelf 중심 탐색 흐름과 사용자별 접근 통제 원칙을 유지한다.

## 2. 기능 요구사항

아래 표는 Feature 5의 목표 범위다. 현재 구현과 후속 작업은 6절에서 구분한다.

| 기능 | 요구사항 |
|---|---|
| 외부 도서 검색 | 제목·저자·출판사 기준 검색, ISBN 중복 제거 |
| 검색 더 보기 | 사용자별 검색 세션을 통해 중단 위치에서 이어서 조회 |
| 검색 결과 표시 | 책 메타데이터와 사용자의 현재 등록 Shelf 표시. 독서 상태 제공은 Feature 6 |
| Shelf에 도서 추가 | 선택한 Shelf에 UserBook 등록 또는 기존 UserBook 연결 |
| Shelf에서 도서 제거 | 해당 ShelfBook 연결만 해제 |
| Shelf별 도서 조회 | 해당 Shelf의 도서·독서 상태·메모·배치 정보·연결 시각 반환 |
| ShelfBook 메모 변경 | 서재별 독립 메모, 최대 2,000자 |
| 독서 상태 변경 | `WANT_TO_READ`, `READING`, `READ` 관리 |

전체 도서 목록·등록 도서 상세 조회·사용자 지정 순서 변경은 [Feature 6](./feature-6-book-browsing-and-ordering.md)으로 분리한다. 문장 수집·필사는 [Feature 7](./feature-7-transcription.md)에서 다룬다. Feature 5는 main에 병합했고, 후속 CD·배포 구축 결과는 [CI/CD 아키텍처](../architecture/ci-cd.md#53-운영-배포-및-cd)에서 관리한다.

외부 도서 검색은 ISBN이 있는 도서를 대상으로 하며, 전자책 본문이나 원문 콘텐츠는 제공하지 않는다.

## 3. 확정된 비즈니스 정책

Feature 5 종료 시점의 등록·변경 코드와 DB 마이그레이션을 기준으로 정리한 정책이다. 구현과 테스트 완료 여부는 6절에서 구분한다. 마이그레이션 파일의 존재가 실제 DB 적용 완료를 뜻하지는 않는다.

### 3.1. Shelf 중심 등록 흐름

- 기본 사용자 흐름은 **Shelf 생성·선택 → 도서 탐색 → 해당 Shelf에 추가**다.
- Shelf가 없다면 첫 Shelf 생성을 안내한다.
- Shelf 목록 조회와 생성에는 기존 `shelfId`가 필요하지 않다.
- 도서를 Shelf에 추가하거나 Shelf 데이터를 조회·변경할 때는 소유권을 검증한다.
- 외부 검색 결과를 조회했다는 사실만으로 UserBook을 등록하지 않는다.

### 3.2. UserBook과 ISBN

- 도서 식별 기준은 ISBN이다. 서로 다른 ISBN은 별도 판본으로 취급한다.
- 동일 사용자의 동일 ISBN은 UserBook 하나로 관리하며, DB의 `(user_id, isbn)` UNIQUE 제약으로 중복 생성을 방지한다.
- 이미 등록된 책을 다른 Shelf에 추가할 때는 기존 UserBook을 재사용한다. 독서 상태는 3.6절을 따르고, 메모는 ShelfBook별로 관리한다.
- 별도의 공용 `books` 테이블은 만들지 않는다.
- 등록에 필요한 제목·저자·출판사·표지 등 메타데이터는 UserBook에 보관한다.
- 출판예정일(`PUBLISH_PREDATE`)은 실제 출판일과 구분하며 검색 표시용으로 취급한다.
- 등록 요청의 ISBN은 검색 결과로 제공한 외부 식별값을 그대로 사용한다. 누락·공백만 거부하며 길이·패턴·체크섬 검증, 하이픈 제거, ISBN-10/13 변환은 적용하지 않는다.
- 신규 UserBook의 메타데이터는 ISBN별 Redis 캐시에서 조회한다. 캐시에 없으면 외부 API의 ISBN 검색을 한 번 호출하고, 첫 페이지에서 요청 ISBN과 정확히 같은 항목 하나를 선택한다. 첫 페이지에서 찾지 못해도 전체 외부 데이터에 도서가 없음을 보장하는 것은 아니며, 실제 응답에서 추가 페이지 문제가 확인되면 정책을 재검토한다.
- 검색 페이징 상태와 메타데이터 캐시는 별개다. 기존 UserBook은 보관된 메타데이터를 재사용한다. 키·수명·프로필별 저장소·호출 순서는 [검색 아키텍처](../architecture/book-search.md#메타데이터-캐시와-검색-세션)에서 관리한다.
- 메타데이터 캐시 조회 장애는 오류로 처리한다. 저장의 연결 실패·타임아웃은 기록하고 계속 진행한다. 신규 메타데이터를 확보하지 못하면 등록 요청 전체를 실패시킨다.

### 3.3. ShelfBook과 데이터 보존

- UserBook과 Shelf는 ShelfBook을 통해 다대다 관계를 이룬다.
- 같은 Shelf에 같은 UserBook을 중복 배치하지 않는다.
- 한 Shelf에서 도서를 제거해도 다른 Shelf의 배치에는 영향을 주지 않는다.
- 마지막 ShelfBook이 제거되어도 UserBook은 보존한다.
- 전체 도서 목록은 **현재 하나 이상의 Shelf에 배치된 UserBook만** 포함한다.
- 도서의 독서 상태는 ShelfBook이 아니라 UserBook에 속한다.
- 메모는 ShelfBook에 속하며 서재마다 독립적이다. 새 연결의 메모는 null이고, 연결 삭제 시 해당 메모도 삭제된다.
- 메모는 null을 허용하고 최대 2,000자로 제한한다. 요청 DTO는 UTF-16 길이, DB 제약은 문자 수로 검사하므로 일부 이모지의 계산은 다를 수 있다. 실제 제약 정의는 [ERD 설명](../database/erd.md#25-shelf_books)과 DTO·V7을 대조한다.
- V6에 ShelfBook 생성 시각, V7에 수정 시각을 정의한다. 목록은 위치 지정 도서 우선 → position 오름차순 → 수정 시각 내림차순 → ID 내림차순으로 반환한다. 메모 수정으로 수정 시각이 바뀌면 위치 미지정 도서의 순서도 바뀐다. 사용자 지정 순서 변경 API는 Feature 6 범위다.
- Shelf 삭제 시 V6의 `ON DELETE CASCADE`로 ShelfBook을 제거하고 UserBook은 보존한다. 연관 데이터가 있는 삭제와 다른 연결·메모 보존은 `ShelfBookManagementIntegrationTest`에서 검증한다.

### 3.4. 사용자별 접근 통제

- UserBook, Shelf, ShelfBook 조회·변경은 인증된 사용자 범위로 제한한다.
- 연결하려는 Shelf와 UserBook이 모두 해당 사용자 소유인지 확인한다.
- 다른 사용자의 검색 세션도 사용할 수 없도록 검색 세션 소유자를 검증한다.
- DB의 외래 키·UNIQUE 제약과 애플리케이션 계층의 소유권 검증을 함께 사용한다.

### 3.5. 동일 Shelf의 중복 등록 처리

**확정 정책:** 화면에서는 대상 Shelf에 이미 등록된 책의 선택을 비활성화하고, 서버에서는 화면 처리와 별개로 같은 책을 등록 대상에서 제외한다.

- 서버는 인증 사용자의 대상 Shelf에 이미 연결된 UserBook을 확인하고 해당 항목을 필터링한다.
- 필터링한 항목은 기존 UserBook의 독서 상태와 ShelfBook 연결·메모를 변경하지 않는다. 같은 연결을 다시 생성하지 않는다.
- 이미 연결된 책이라는 이유로 중복 오류나 409를 반환하지 않는다. 중복 항목과 신규 연결 대상이 섞여 있으면 신규 연결 대상만 처리한다.
- 모든 항목이 이미 연결돼 있으면 등록에 따른 데이터 변경 없이 처리한다. 중복 자체를 실패 사유로 삼지 않는다.
- DB의 `UNIQUE(shelf_id, user_book_id)`는 중복 행 저장을 막는 제약으로 유지한다.

이 정책은 **DB에 이미 존재하는 대상 Shelf 연결**에 대한 것이다. 요청 목록 안의 중복 ISBN은 잘못된 요청으로 400 처리한다. 응답에는 새로 연결한 ISBN·ShelfBook ID만 포함하며, 전부 제외되면 빈 `books` 배열을 반환한다. 동시 등록으로 DB UNIQUE 충돌이 발생하면 `DUPLICATE_REGISTRATION`으로 변환해 409를 반환한다.

### 3.6. 등록 시 독서 상태와 재등록 처리

신규·기존·재등록 도서 모두 화면에서 독서 상태를 선택할 수 있다. 화면에는 기본 상태를 표시하고, 등록 요청에는 각 도서의 최종 선택값을 항상 보낸다. 서버는 `readingStatus`를 필수로 검증하며, 생략·null·유효하지 않은 값은 400으로 거부한다.

서버는 먼저 3.5절에 따라 대상 Shelf의 중복 항목을 제외하고, 나머지 항목에 아래 규칙을 적용한다.

| 기존 UserBook 상태 | UserBook 처리 | 독서 상태 | 새 ShelfBook 메모 |
|---|---|---|---|
| 행 없음 | 새 행 생성 | 요청값 적용 | null |
| 행 있음·다른 Shelf 연결 있음 | 기존 행 재사용 | 요청값 적용 | null. 다른 연결의 메모 유지 |
| 행 있음·어느 Shelf에도 연결 없음 | 기존 행 재사용(재등록) | 요청값 적용 | null |

재등록 시 독서 상태는 요청값을 적용하고, 삭제된 ShelfBook의 메모를 복원하지 않는다. UserBook의 메모 초기화 분기는 더 이상 없다. 기존 메타데이터는 자동 갱신하지 않으며, 독서 상태 변경은 해당 UserBook을 공유하는 모든 Shelf에 반영된다.

3.5~3.6절은 Feature 5에서 적용한 등록 정책의 기록이다. 이후 변경에 적용할 기준은 현행 정책 문서이며, 당시 완료 결과는 이 문서에 보존한다. 정책 확정과 실제 구현·테스트 완료 여부는 구분한다.

### 3.7. 수정·다건 삭제 API

이 절은 입력·소유권·실패 시 처리 정책을 정의한다. 경로·요청 DTO·성공 응답의 실제 계약은 다음 웹 Adapter와 생성 OpenAPI를 기준으로 확인한다.

- [등록 Controller](../../src/main/java/com/myshelf/book/adapter/in/web/registration/ShelfBookAddController.java)
- [메모·다건 삭제 Controller](../../src/main/java/com/myshelf/book/adapter/in/web/shelfBook/ShelfBookController.java)
- [독서 상태 Controller](../../src/main/java/com/myshelf/book/adapter/in/web/userBook/UserBookController.java)
- [Shelf·도서 목록 Controller](../../src/main/java/com/myshelf/shelf/adapter/in/web/ShelfController.java)

- ShelfBook의 조회·변경·삭제는 연결된 Shelf의 소유권을 기준으로 확인한다. UserBook의 독서 상태 변경은 UserBook 소유권을 확인한다.
- 미존재·타인 소유 대상은 구분하지 않고 404를 반환한다.
- 다건 삭제는 빈 목록·null 원소·중복 ID를 거부한다. 요청 ID 중 하나라도 조회되지 않으면 삭제 전에 404로 거부하며, 전체 성공 또는 전체 실패로 처리한다.
- 메모는 JSON 본문으로 받는다. `memo: null` 또는 필드 누락은 null로 변경하고, 빈 문자열은 그대로 저장한다.
- 등록·변경·삭제는 각 업무의 DB 쓰기를 원자적으로 처리한다. Writer·Service·Adapter별 실제 트랜잭션 경계는 [도서 관리 구조](../architecture/book-management.md)에서 관리한다.
- 목록 조회는 Shelf 자체의 존재·소유권을 먼저 확인한다. 본인 소유의 빈 서재는 200과 빈 배열, 없는·타인 소유 서재는 404다. ShelfBook 목록의 빈 결과만으로는 두 상황을 구분할 수 없다.

## 4. 외부 도서 검색 설계 및 현재 구현

이 절의 현재 구현은 Feature 5 종료 시점을 뜻한다. 이후 처리 흐름·설정은 검색 아키텍처를 확인한다.

### 4.1. 현재 제공하는 기능

최초 검색과 검색 ID 기반 더 보기를 구현했다. 현재 응답은 `searchId`, `books`, `hasNext`이며, 도서별 메타데이터와 인증 사용자의 등록 Shelf 목록을 포함한다.

**독서 상태는 아직 제공하지 않는다.** 등록 Shelf는 현재 연결된 서재만 뜻한다. UserBook이 없거나 UserBook만 남고 Shelf 연결이 없는 경우 모두 등록된 서재가 없는 것으로 표시하며, UserBook 행의 존재 여부를 별도 표시하지 않는다.

검색어는 누락·공백 입력을 거부하고 앞뒤 공백을 `strip()`으로 제거한다. 최대 길이 제한은 현재 없다.

### 4.2. 상세 설계 참조

이 문서는 기능 범위와 완료 기준을 관리한다. 검색 상태 필드와 설정값은 아래 문서에서 관리한다.

- 최초 검색·더 보기·소유권 검증: [검색 흐름](../architecture/book-search.md#최초-검색과-더-보기)
- Redis·InMemory의 프로필별 선택과 만료 설정: [현재 저장소 구성](../architecture/book-search.md#현재-구현-상태)
- 페이지 크기·조회 라운드 상한·종료 조건: [페이징·종료 정책](../architecture/book-search.md#페이징종료-정책)
- 상태 구성과 `hasNext`의 선택 근거: [ADR-012](../decisions/012-stateful-book-search-pagination.md#유지할-검색-상태)
- 외부 필드 실패 시 부분 결과 거부·시간 제한·HTTP 응답: [오류 처리](../architecture/book-search.md#오류-처리)

동일 사용자·검색 ID의 동시 더 보기 요청은 단일 JVM에서 차단한다. Redis 상태 공유만으로 서버 간 동시 처리가 원자적으로 실행되는 것은 아니며, 서버 간 요청 제어는 아직 구현하지 않았다.

## 5. 도서 등록·관리 시나리오

Feature 5의 구현 흐름이다. 현재 외부 검색 응답의 범위는 4.1절과 같고, 전체 도서·상세 조회는 후속 기능이다.

1. 사용자가 자신의 Shelf를 선택한다.
2. 키워드로 도서를 검색하고, 필요한 경우 더 보기를 요청한다.
3. 검색 결과에서 메타데이터·소속 Shelf를 확인하고, 등록할 때 독서 상태를 선택한다.
4. 선택한 도서를 Shelf에 추가한다. 대상 Shelf의 중복 항목은 3.5절에 따라 서버에서도 제외한다.
5. 처음 등록하는 ISBN이면 UserBook을 생성하고 ShelfBook으로 연결한다.
6. 이미 등록한 ISBN이면 기존 UserBook을 재사용하고 요청한 독서 상태를 적용한 뒤, 메모가 null인 새 ShelfBook을 연결한다.
7. 여러 Shelf에서 같은 UserBook을 조회하더라도 독서 상태는 동일하다.
8. Shelf에서 책을 제거하면 해당 ShelfBook만 삭제한다.
9. 마지막 Shelf에서 제거한 도서는 전체 도서 목록에서 제외하되 UserBook은 보존한다.
10. Shelf별 목록에서 등록 결과·독서 상태·메모를 확인한다. 사용자 지정 순서 변경은 Feature 6에서 추가한다.

#### 후속 구현·실험 — 병합 우선순위와 외부 조회 크기

먼저 조회 묶음 내 기본 노출 순서를 명시하고, 같은 병합 정책에서 외부 조회 크기를 비교한다. 아래 우선순위 병합은 아직 구현하지 않았다.

- [ ] `BookSearchField`에 `int priority`를 추가한다. `TITLE(1)`, `AUTHOR(2)`, `PUBLISHER(3)`으로 지정하고 낮은 값부터 병합한다.
- [ ] `NationalLibraryBookAdapter`에서 입력 Map의 순회 순서 대신 `priority`를 기준으로 결과를 꺼내 병합한다. 이번 조회에서 소진되어 포함되지 않은 필드는 건너뛴다.
- [ ] Map의 삽입 순서와 병렬 작업의 완료 순서가 달라도 제목 → 저자 → 출판사 순으로 병합되는지 검증한다.
- [ ] 동일 ISBN은 먼저 병합된 필드의 메타데이터가 남고, 더 보기에서도 `pendingBooks` 순서가 유지되는지 검증한다.

우선순위는 **같은 외부 조회 묶음 안에서만** 적용한다. 제목 검색의 전체 페이지를 먼저 소진하는 방식은 채택하지 않는다. 병렬 호출·ISBN 중복 제거·검색 세션 구조는 유지하고, 기존 버퍼 뒤에 새 조회 결과를 추가한다. 이미 반환한 도서는 재정렬하지 않는다. 먼저 선택된 메타데이터가 더 정확하다는 뜻도 아니다.

외부 API 페이지와 사용자 응답 크기를 분리하고 미반환 도서를 보관하는 구조는 유지한다. 이 버퍼는 같은 검색 세션의 다음 요청을 위한 선조회 결과이며, 사용자 간 응답을 공유하는 캐시는 아니다. 현재 외부 페이지 크기를 최적값으로 판단할 측정 근거는 아직 없다.

- [ ] 외부 페이지 크기 20·50·100건을 같은 검색어·병합 정책으로 비교한다. 설정 변경 사이에는 기존 세션을 재사용하지 않고 새 검색을 시작한다.
- [ ] 첫 응답 시간, 중복 제거 후 고유 ISBN 수, 최초 반환 후 버퍼 크기·Redis 저장량을 기록한다.
- [ ] 최초 검색 후 최대 5번 더 보기까지의 외부 HTTP 호출 수와 필드별 노출 시점을 비교한다. 결과가 먼저 소진되면 종료한다.

페이지 크기를 줄여도 첫 라운드에서 조회하는 필드 수가 같으면 HTTP 호출 수는 같다. 비교할 것은 선조회·저장 비용과 이후 더 보기의 추가 호출 비용이다. 제목 우선 병합을 적용하면 큰 페이지가 저자·출판사 결과 노출을 늦출 수 있으므로, 속도뿐 아니라 노출 순서도 함께 본다. 필드 우선순위는 관련도 정확성을 보장하는 기준으로 취급하지 않는다.

측정 차이가 작다면 작은 페이지 크기를 우선 후보로 검토하되, 지금 값을 확정하지 않는다. 변경 시 요청의 `page_size`, `calculateNextPage()`와 관련 테스트를 함께 확인한다. 현재는 즉시 구조를 재설계할 결함이 확인된 상태가 아니라, 측정 후 조정할 개선 과제로 남긴다. 이 실험을 도서 등록·Shelf 연결 구현의 선행 조건으로 두지는 않는다.

## 7. 후속 검토할 정책

| 주제 | 결정할 사항 |
|---|---|
| Shelf별 목록 페이징 | 현재 전체 목록 반환. 페이징 도입 여부는 데이터 규모에 따라 후속 검토 |
| 책 순서 변경 | Feature 6에서 `position` 시작값·재정렬 요청 방식 확정 |
| 검색어 길이 | 현재 최대 길이 제한 없음. 제한 도입 여부와 기준 |
| 도서정보 이상 | 필수 메타데이터 누락 시 개별 제외 또는 실패 |
| 독서 날짜 | 시작일·완독일은 현재 미구현이며 이번 종료 조건에 포함하지 않음 |

현재 독서 상태 변경 코드는 enum의 세 상태 사이 전환을 별도로 제한하지 않는다. 등록 요청은 ISBN·필수 독서 상태만 받으며, 메타데이터는 서버에서 확보한다. Shelf 삭제의 연결 제거는 V6 CASCADE 정책을 따른다.

미결정 정책은 구현 편의만으로 확정하지 않고, 선택 이유와 테스트 기준을 남긴다.
