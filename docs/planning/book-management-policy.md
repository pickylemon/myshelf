# 현행 도서 관리 정책

이 문서는 여러 Feature에 걸쳐 유지되는 현재 도서 관리 규칙의 기준이다. 정책을 변경하면 이 문서를 갱신한다. 개발 당시의 범위·판단·검증 결과는 [Feature 4](feature-4-shelf-management.md)와 [Feature 5](feature-5-book-management.md)에 보존한다.

처리 구조는 [도서 관리 아키텍처](../architecture/book-management.md), 검색·캐시 동작은 [검색 아키텍처](../architecture/book-search.md), 데이터 제약은 [ERD 설명](../database/erd.md)에서 확인한다. API 경로·요청·응답의 세부 정의는 Controller·DTO와 생성 OpenAPI를 기준으로 확인한다.

## 1. 등록과 도서 식별

- 등록에는 대상 Shelf와 도서별 ISBN·독서 상태가 필요하다. 외부 검색만으로 UserBook·ShelfBook을 생성하지 않는다. 검색 메타데이터의 Redis 캐싱과 사용자 도서 등록은 별개다.
- 동일 사용자의 동일 ISBN은 하나의 UserBook으로 관리한다. ISBN이 다르면 별도 도서로 취급한다.
- ISBN은 외부 식별값 그대로 사용한다. 누락·공백은 거부하지만 정규화·체크섬 검증·ISBN-10/13 변환은 적용하지 않는다.
- UserBook이 없으면 서버에서 메타데이터를 확보해 생성한다. 필요한 메타데이터를 확보하지 못하면 등록 요청 전체를 실패시킨다. 기존 UserBook은 재사용하며 메타데이터를 자동 갱신하지 않는다.
- 한 UserBook을 여러 Shelf에 연결할 수 있다. 같은 Shelf에는 같은 UserBook을 중복 연결하지 않는다.

## 2. 중복 등록과 요청의 원자성

- 대상 Shelf에 이미 연결된 도서는 등록 대상에서 제외한다. 해당 UserBook의 독서 상태와 기존 ShelfBook·메모는 변경하지 않는다.
- 기존 연결과 신규 연결 대상이 섞여 있으면 신규 연결 대상만 처리한다. 모두 기존 연결이면 데이터 변경 없이 성공한다.
- 등록 응답에는 새로 연결한 ISBN·ShelfBook ID만 포함한다. 새 연결이 없으면 빈 `books` 배열을 반환한다.
- 하나의 요청 안에 중복 ISBN이 있으면 400으로 거부한다. 이는 이미 존재하는 Shelf 연결을 제외하는 정책과 다르다.
- 동시 등록으로 중복 제약 충돌이 발생하면 409를 반환한다. 이미 연결된 항목을 사전에 제외하는 처리와 구분한다.
- 등록 요청의 DB 변경은 전체 성공 또는 전체 실패로 처리한다. 앞선 도서의 생성·독서 상태 변경·연결도 뒤 항목의 DB 쓰기 실패 시 함께 롤백한다. 공용 메타데이터 캐시는 이 DB 롤백의 대상이 아니다.

## 3. 독서 상태와 재등록

- 독서 상태는 UserBook에 속하며 같은 UserBook을 사용하는 모든 Shelf에서 공유한다.
- 상태는 `WANT_TO_READ`, `READING`, `READ`이며 상태 사이의 전환을 별도로 제한하지 않는다.
- 등록 요청의 도서별 독서 상태는 필수다. 서버가 생략된 값을 기본 상태로 채우지 않는다. 화면의 기본 선택값 정책과 구분한다.
- 신규 UserBook과 기존 UserBook의 새 Shelf 연결 모두 요청한 상태를 적용한다. 단, 2절에서 제외한 기존 Shelf 연결 항목에는 적용하지 않는다.
- 모든 Shelf에서 제거했던 도서를 재등록하면 기존 UserBook을 재사용하고 요청한 상태를 적용한다. 삭제한 연결의 메모는 복원하지 않는다.
- 동일 상태를 다시 요청한 것만으로 수정 시각 갱신을 보장하지 않는다. 실제 변경에 따른 갱신 방식은 아키텍처에서 설명한다.

## 4. 메모와 삭제 후 데이터 보존

- 메모는 ShelfBook별로 독립적으로 관리한다. 다른 Shelf의 같은 도서 메모에는 영향을 주지 않는다.
- 새 연결의 메모는 null이다. null과 빈 문자열을 허용하며 최대 2,000자로 제한한다. 현재 요청 검증과 DB의 문자 계산 차이는 [ERD 설명](../database/erd.md#25-shelf_books)을 참고한다.
- 메모 수정 요청에서 `memo: null` 또는 필드 누락은 null로 변경한다. 빈 문자열은 그대로 저장한다.
- 도서를 Shelf에서 제거하면 해당 ShelfBook과 메모만 삭제한다. 다른 Shelf 연결과 UserBook은 보존한다.
- 마지막 ShelfBook을 삭제해도 UserBook과 독서 상태·메타데이터는 보존한다.
- Shelf를 삭제하면 해당 Shelf의 연결과 메모를 삭제한다. 다른 Shelf의 연결과 UserBook은 보존한다.

## 5. 접근 통제와 다건 삭제

- 도서 관리 기능은 인증된 사용자의 리소스에만 적용한다. 등록할 Shelf와 연결할 UserBook의 소유자가 일치해야 한다.
- 미존재 대상과 타인 소유 대상은 구분하지 않고 404로 처리한다.
- 다건 삭제는 ShelfBook ID를 받는다. 빈 목록·null 원소·중복 ID는 거부한다.
- 삭제 대상 중 하나라도 미존재하거나 타인 소유이면 삭제 전에 전체 요청을 404로 거부한다. 일부 대상만 삭제하지 않는다.
- 본인 소유의 빈 Shelf에 대한 도서 목록은 200과 빈 배열을 반환한다. 미존재·타인 소유 Shelf는 404다.

## 6. 조회 범위와 후속 기능

현재는 Shelf별 도서 목록을 제공한다. 독서 상태는 사용자별로 공유하고 메모·배치 정보는 Shelf별로 구분한다. 기본 정렬의 실제 순서는 [목록 조회 구조](../architecture/book-management.md#5-목록-조회와-모델-변환)에서 관리한다.

전체 서재 검색·목록·등록 도서 상세·사용자 지정 순서 변경과 검색 응답의 독서 상태 제공은 [Feature 6](feature-6-book-browsing-and-ordering.md)의 후속 범위다. 연결이 없는 UserBook을 전체 관리 목록에서 제외하는 요구사항은 해당 계획에서 다루며, 현재 API가 구현된 것으로 해석하지 않는다.
