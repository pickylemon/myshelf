# 도서 메타데이터 API 선정 계획

- **작성일:** 2026-10-26
- **최종 수정일:** 2026-10-29
- **상태:** 검토 중
- **관련 기능:** Feature 5 — 외부 도서 검색 및 사용자별 도서 관리
- **관련 결정:** [ADR-011 — 사용자별 도서 메타데이터 스냅샷 저장](../decisions/011-user-book-metadata-snapshot.md)

## 1. 목적

MyShelf는 사용자가 외부 도서 검색 API를 통해 책을 찾고 자신의 Shelf에 등록하여 관리하는 서비스이다.

사용자가 도서의 기본 정보를 직접 입력하지 않도록 외부 API에서 메타데이터를 조회하여 활용한다.

다만 MyShelf의 핵심 목적은 풍부한 도서정보 제공이 아니라 **사용자별 Shelf 구성과 독서 상태 관리**이다.

따라서 외부 API를 선정할 때 도서정보의 양뿐 아니라 실제 검색 품질, 최소 메타데이터의 정확성, 저장 및 재사용 조건, 연동 복잡성을 우선 고려한다.

본 문서는 외부 도서 메타데이터 API의 후보 비교, 선정 기준, 실제 검증 결과 및 미결정 사항을 기록한다.

최종 API 선정 결과와 근거는 검증을 완료한 후 별도 ADR로 기록한다.

## 2. 요구사항

### 2.1. 기능 요구사항

- ISBN이 있는 도서를 등록 대상으로 한다.
- 사용자는 하나의 검색어(`keyword`)로 도서를 검색할 수 있어야 한다.
- 제목, 저자, 출판사 기반 검색을 지원하는 것을 목표로 한다.
- ISBN 직접 검색은 일반 사용자 검색의 필수 UI가 아니며, 필요 시 추가할 수 있다.
- 외부 검색 결과 중 유효한 ISBN을 가진 도서만 등록할 수 있다.
- 도서 등록에 필요한 ISBN, 제목, 저자, 출판사, 표지 이미지 URL을 가능한 범위에서 제공해야 한다.
- 검색 결과에는 사용자가 이미 등록한 도서의 독서 상태 및 Shelf 정보를 표시할 수 있어야 한다.
- 외부 API 검색과 사용자 도서 등록은 별도의 작업으로 구분한다.
- 외부 API 장애가 이미 등록된 도서의 조회를 방해해서는 안 된다.

### 2.2. 서비스 범위

MyShelf는 다음 기능에 집중한다.

- 사용자별 Shelf 생성 및 관리
- 도서의 Shelf 등록 및 제거
- 하나의 도서를 여러 Shelf에 연결
- 사용자별 독서 상태 관리
- Shelf 내 도서 정렬
- 사용자의 전체 Shelf를 대상으로 한 도서 검색

외부 도서 API가 제공하는 다음 정보는 초기 기능에서 직접 관리하지 않는다.

- 책소개, 목차, 서평
- 도서 가격 및 판매 정보
- 상세 판본·시리즈 정보
- 페이지 수 및 출판 관련 세부 정보

사용자가 더 자세한 도서정보를 확인하고 싶다면 향후 외부 서점 또는 도서정보 사이트의 상세 페이지로 이동하는 기능을 고려한다.

단, 외부 상품 상세 페이지 URL을 제공하는 방법은 별도 검토가 필요하다.

### 2.3. 기존 데이터 모델 및 변경 방향

현재 `user_books` 테이블은 다음 정보를 관리한다.

- `id`: 사용자 도서 식별자
- `user_id`: 도서 소유자
- `isbn`: 도서 식별 기준
- `title`: 도서 제목
- `author`: 저자
- `reading_status_code`: 사용자별 독서 상태

`UNIQUE(user_id, isbn)` 제약조건으로 동일 사용자의 ISBN 중복 등록을 방지한다.

동일한 `UserBook`을 여러 Shelf에 등록하는 경우 `shelf_books`를 통해 연결한다.

도서가 모든 Shelf에서 제거되어도 `UserBook`은 유지한다.

[ADR-011](../decisions/011-user-book-metadata-snapshot.md)에 따라 별도의 공통 `Book` 엔티티는 도입하지 않으며, `UserBook`에 최소한의 도서 메타데이터를 저장한다.

추가 저장 대상으로 결정한 정보는 다음과 같다.

- `publisher`: 출판사
- `cover_image_url`: 표지 이미지 URL

위 필드는 기존 데이터 모델에 반영해야 할 변경 사항이며, 실제 엔티티 및 Flyway 마이그레이션 적용 여부는 구현 과정에서 확인한다.

## 3. 외부 API 후보

### 3.1. 국립중앙도서관 ISBN 서지정보 API

국내 ISBN 발급 출판 자료의 서지정보를 제공하는 공공 API이다.

**주요 특징**

- ISBN, 제목, 저자, 출판사 등 조회
- 표지 이미지 URL 제공 가능
- ISBN, 제목, 저자, 출판사별 검색 조건 지원
- JSON 및 XML 응답 지원
- 별도 인증키 필요
- 공공데이터포털에 데이터 이용 조건 안내

**검토 사항**

- 국내 도서 검색 성공률
- 제목·저자·출판사 검색 품질
- ISBN 및 필수 메타데이터 정확성
- 표지 이미지 제공률과 접근 가능 여부
- 데이터 장기 저장 및 재사용 조건
- API 호출 제한 및 장애 처리
- 통합 검색 미지원에 따른 추가 구현 복잡성

ISBN 검색은 우절단 방식이므로 특정 ISBN을 정확히 조회하려는 경우 응답의 ISBN과 요청 ISBN을 별도로 비교해야 한다.

**현재 평가:** 국내 도서 검색을 위한 우선 검증 후보이며, 실제 연동 실험을 시작한 상태이다.

### 3.2. 카카오 Daum 책 검색 API

Daum 책 검색 서비스를 통해 도서 메타데이터를 제공하는 API이다.

**주요 특징**

- 키워드 및 도서 관련 검색 조건 지원
- 제목, 저자, 출판사, 표지 이미지, 소개 등 제공
- REST API 및 JSON 응답
- REST API 키를 통한 인증
- 기존 공식 문서 조사 기준 책 검색 무료 쿼터 제공

**검토 사항**

- 국내 도서 검색 품질
- ISBN-10 및 ISBN-13 응답 처리
- 검색 결과의 장기 저장·재사용 허용 범위
- 호출 제한과 무료 쿼터
- 필수 메타데이터 누락 가능성
- 통합 검색 및 페이징 처리 편의성

특히 ISBN-10과 ISBN-13이 하나의 문자열로 제공될 수 있으므로 정규화 정책을 검토해야 한다.

**현재 평가:** 검색 기능의 편의성 측면에서 비교할 가치가 있으나 데이터 저장·재사용 조건의 확인이 필요하다.

### 3.3. 도서관 정보나루

도서관 빅데이터 기반의 도서 상세정보 및 대출 관련 정보를 제공한다.

**주요 특징**

- ISBN 기반 도서 상세정보 조회
- 제목, 저자, 출판사, 이미지 URL 등 제공
- 도서관 대출 관련 부가 정보 활용 가능

**검토 사항**

- 국내 도서 데이터 수록 범위
- 검색 및 응답 형식
- 이용 조건과 호출 제한
- 현재 기능에서 추가 연동할 실익

**현재 평가:** 도서 상세 조회 및 향후 통계 기능의 보조 후보이다.

### 3.4. Google Books API

Google Books의 도서 메타데이터를 조회할 수 있는 API이다.

**주요 특징**

- ISBN 및 도서 키워드 검색
- 제목, 저자, 출판사 등 메타데이터 제공
- 국내외 도서 검색 가능

**검토 사항**

- 국내 도서 검색 품질
- 한글 도서 메타데이터 정확성
- 데이터 저장 및 재사용 조건

**현재 평가:** 해외 도서 지원 필요성이 생기면 검토할 후보이다.

### 3.5. 제외 후보

**네이버 책 검색 API**

기존 조사에서 2026년 7월 31일 서비스 종료가 확인되어 신규 연동 후보에서 제외하였다.

## 4. 국립중앙도서관 API 실제 검증

### 4.1. 호출 및 응답 확인

2026-10-29 기준으로 ISBN 서지정보 API에 직접 요청하여 JSON 응답을 확인하였다.

검증 요청의 주요 조건은 다음과 같다.

```text
result_style=json
page_no=1
page_size=2
title=제과
```

인증키는 요청에 필요하지만 문서에 기록하지 않는다.

**확인한 최상위 응답 구조**

```json
{
  "TOTAL_COUNT": "1297",
  "PAGE_NO": "1",
  "docs": [
    { "..." : "도서 정보" },
    { "..." : "도서 정보" }
  ]
}
```

실제 응답에서 다음 사실을 확인하였다.

- `TOTAL_COUNT`, `PAGE_NO`는 문자열로 반환된다.
- 도서 목록은 `docs` 배열에 포함된다.
- ISBN은 `EA_ISBN` 필드로 제공된다.
- 도서 제목, 저자, 출판사는 각각 `TITLE`, `AUTHOR`, `PUBLISHER` 필드로 제공된다.
- 표지 이미지 URL은 `TITLE_URL`에 포함될 수 있다.
- 응답에 존재하는 필드라도 값은 빈 문자열일 수 있다.
- 저자 정보에는 `저자 :` 등의 표현이 포함될 수 있다.
- 목차, 책소개, 서평 등 상세정보는 일부 자료에서만 제공된다.

이번 요청에서는 총 검색 건수 1,297건, 응답 도서 2건을 확인하였다.

두 도서 중 한 건만 표지 URL과 일부 상세정보를 제공하였다.

이는 제한된 샘플의 관찰 결과이며, 전체 도서 데이터의 필드 제공률을 의미하지 않는다.

### 4.2. MyShelf에서 활용할 응답 필드

**최상위 응답**

| 필드 | 용도 |
|---|---|
| `TOTAL_COUNT` | 외부 검색의 전체 결과 건수 |
| `PAGE_NO` | 외부 검색 페이지 번호 |
| `docs` | 검색된 도서 목록 |

**도서 정보**

| 필드 | MyShelf 용도 | 저장 여부 |
|---|---|---|
| `EA_ISBN` | 도서 식별·등록 | 저장 |
| `TITLE` | 도서 제목 표시 | 저장 |
| `AUTHOR` | 저자 표시 | 저장 |
| `PUBLISHER` | 출판사 표시 | 저장 |
| `TITLE_URL` | 표지 이미지 표시 | URL 저장 |
| `BOOK_INTRODUCTION` | 책소개 | 저장하지 않음 |
| `BOOK_TB_CNT` | 목차 | 저장하지 않음 |
| `BOOK_SUMMARY` | 서평 | 저장하지 않음 |
| `PAGE` | 페이지 수 | 저장하지 않음 |
| `FORM` | 발행 형태 | 저장하지 않음 |

초기 구현에서는 최소 메타데이터만 매핑하며, 불필요한 외부 응답 필드를 내부 도메인 모델에 포함하지 않는다.

ISBN과 제목은 등록을 위한 필수 정보로 취급한다.

저자, 출판사, 표지 URL은 제공되지 않을 수 있으므로 누락을 허용한다.

### 4.3. 아직 검증하지 않은 사항

- 다양한 도서 유형에 대한 검색 성공률
- ISBN 정확 검색 시 결과 일치 여부
- 제목·저자·출판사 검색 결과의 품질
- 표지 이미지의 실제 제공률
- 외부 API 응답 시간
- 호출 제한 및 장애 응답
- 장기 저장 및 표지 이미지 표시의 이용 조건

따라서 실제 JSON 응답을 확인했다는 이유만으로 최종 API 선정이 완료된 것은 아니다.

## 5. MyShelf의 외부 검색 정책

### 5.1. 사용자 검색 인터페이스

사용자에게는 하나의 검색 입력창을 제공한다.

```http
GET /books/search?keyword=제과&page=1
```

- `keyword`: 사용자가 입력한 검색어
- `page`: 페이지 번호, 기본값 1
- `pageSize`: 사용자 입력 없이 서버 정책으로 관리

초기 페이지 크기는 20건을 기준으로 한다.

페이지 크기는 Application Service의 정책으로 관리하며, 외부 API의 요청 건수와 반드시 같아야 하는 것은 아니다.

### 5.2. 외부 API 검색 조건 매핑

국립중앙도서관 ISBN API는 제목·저자·출판사 검색 파라미터를 각각 제공하지만, 이 세 필드를 대상으로 하는 단일 통합 검색 파라미터는 확인되지 않았다.

검토 중인 구현 방식은 하나의 `keyword`를 다음 검색 조건에 각각 전달하는 것이다.

```text
MyShelf keyword
    ├── title
    ├── author
    └── publisher
          ↓
     검색 결과 병합
          ↓
     ISBN 기준 중복 제거
```

다만 다음 문제가 남아 있다.

- 여러 검색 결과를 어떤 기준으로 정렬할 것인가?
- 중복 제거 후 페이지 크기를 어떻게 보장할 것인가?
- 각 검색 조건의 `TOTAL_COUNT`를 어떻게 처리할 것인가?
- 동일 도서가 서로 다른 페이지에 나타날 가능성을 어떻게 다룰 것인가?
- 세 번의 외부 호출이 응답 시간과 호출량에 미치는 영향은 어느 정도인가?

**세 검색 결과를 단순 병합하는 방식은 아직 확정하지 않는다.**

통합 검색을 제공하는 다른 API와 비교한 후 검색 품질과 페이징 복잡성을 고려하여 결정한다.

국립중앙도서관의 소장자료 검색 API처럼 통합 검색을 지원하는 별도 API도 검토할 수 있으나, ISBN 제공 여부와 실제 데이터 품질을 확인해야 한다.

### 5.3. 등록 가능한 검색 결과

외부 검색 결과 중 유효한 ISBN과 제목이 있는 도서만 등록할 수 있다.

저자, 출판사, 표지 URL이 누락되어도 등록은 가능하도록 설계한다.

ISBN 형식 및 정규화 정책은 구현 과정에서 확정한다.

## 6. API 선정 기준 및 검증 계획

### 6.1. 선정 기준

| 평가 항목 | 중요도 | 확인 내용 |
|---|---|---|
| 국내 도서 검색 품질 | 높음 | 제목·저자·출판사 검색 성공률 |
| ISBN 정확성 | 높음 | 도서 식별 및 중복 제거 가능 여부 |
| 기본 메타데이터 | 높음 | ISBN·제목·저자·출판사·표지 |
| 데이터 이용 조건 | 높음 | 장기 저장 및 표지 표시 허용 여부 |
| 검색·페이징 구현 복잡성 | 높음 | 통합 검색, 병합, 정렬, 페이지 처리 |
| 개발 편의성 | 중간 | 인증, 응답 구조, 공식 문서 |
| 호출 제한 | 중간 | 무료 쿼터 및 요청 제한 |
| 서비스 안정성 | 중간 | 응답 지연, 오류, 장애 처리 |

MyShelf는 외부에서 조회한 도서의 기본 메타데이터를 `UserBook`에 보존하므로 **데이터 저장 및 재사용 허용 여부를 필수 조건**으로 평가한다.

### 6.2. 대표 도서 검증

국립중앙도서관과 카카오를 우선 비교한다.

대표 도서 약 10권을 선정하여 다음 유형을 포함한다.

- 국내 일반 단행본
- 국내 IT 및 기술 서적
- 번역서
- 오래된 도서
- 최근 출간 도서
- 개정판이 있는 도서
- 절판 도서

ISBN 직접 조회뿐 아니라 제목·저자 키워드 검색도 테스트한다.

### 6.3. 검증 항목

| 항목 | 확인 방법 |
|---|---|
| 검색 성공 | 해당 도서를 찾을 수 있는가 |
| ISBN 정확성 | 예상 ISBN과 일치하는가 |
| 제목·저자 | 정확한 정보를 제공하는가 |
| 출판사 | 정보가 제공되는가 |
| 표지 | URL 존재 여부와 접근 가능 여부 |
| 키워드 검색 | 통합 검색 품질이 충분한가 |
| 페이징 | 일관된 정렬과 페이지 처리가 가능한가 |
| 응답 시간 | 호출이 과도하게 지연되지 않는가 |
| 이용 조건 | 메타데이터 저장·재사용·표시가 허용되는가 |

### 6.4. 예외 상황 검증

- 검색 결과가 없는 경우
- 잘못된 ISBN 형식
- ISBN이나 제목이 누락된 응답
- ISBN 우절단 검색으로 다른 ISBN이 반환되는 경우
- 표지 URL이나 저자 정보가 비어 있는 경우
- 인증 실패
- 호출 제한 초과
- 응답 지연 및 외부 API 장애
- 예상하지 못한 JSON 응답 구조

## 7. MyShelf 도서 검색 및 등록 흐름

### 7.1. 외부 도서 검색

```text
사용자
 └─ Shelf 선택
     └─ 도서 추가
         └─ keyword 입력
             └─ 외부 도서 검색
                 └─ 기존 UserBook·Shelf 등록 정보 결합
                     └─ 검색 결과 표시
                         └─ 도서 선택 및 등록 확정
```

외부 검색만으로 DB에 저장하지 않는다.

도서 등록을 확정하면 다음과 같이 처리한다.

1. ISBN으로 기존 사용자 도서 등록 여부를 확인한다.
2. 기존 `UserBook`이 없다면 최소 메타데이터를 저장하여 생성한다.
3. 기존 `UserBook`이 있다면 재사용하고 메타데이터는 자동 갱신하지 않는다.
4. 선택한 Shelf와 `UserBook`을 `shelf_books`로 연결한다.
5. 독서 상태는 `UserBook` 수준에서 관리한다.

독서 상태는 기존 등록값이 있으면 유지하는 것을 기본으로 하고, 사용자가 명시적으로 변경하면 해당 변경을 반영한다. 신규 도서는 별도 지정이 없으면 `WANT_TO_READ`를 기본으로 한다.

이미 동일 Shelf에 연결된 도서는 중복 등록하지 않는다.

### 7.2. 내 서재 전체 검색

```text
사용자
 └─ 전체 Shelf에서 검색
     └─ MyShelf DB 조회
         └─ shelf_books + user_books
             └─ 중복 없는 검색 결과 반환
```

- 외부 API를 호출하지 않는다.
- 사용자가 소유한 Shelf에 현재 연결된 도서만 검색한다.
- Shelf 연결이 없는 `UserBook`은 전체 Shelf 검색 결과에서 제외한다.
- 동일한 `UserBook`이 여러 Shelf에 속해도 중복 반환하지 않는다.

### 7.3. 헥사고날 아키텍처 적용

```text
BookController
    ↓
ExternalBookSearchUseCase
    ↓
ExternalBookSearchService
    ├── ExternalBookSearchPort
    │       └── NationalLibraryBookAdapter
    │               └── 외부 API
    │
    └── BookRegistrationLookupPort
            └── Persistence Adapter
                    └── PostgreSQL
```

외부 API 응답 DTO와 MyShelf의 Application 모델, Web 응답 DTO는 분리한다.

외부 API의 필드명이나 응답 구조가 Domain 및 Application Service에 직접 유입되지 않도록 한다.

### 7.4. 외부 API 장애 처리

외부 API 장애는 신규 도서 검색에 영향을 줄 수 있다.

그러나 이미 등록된 `UserBook`에는 최소 메타데이터가 저장되어 있으므로 Shelf 조회와 내부 검색은 외부 API 없이 처리한다.

외부 API 호출의 타임아웃, 오류 응답 매핑, 재시도 여부는 구현 및 검증 과정에서 결정한다.

## 9. 현재 결론

MyShelf는 외부 도서 API를 사용하여 등록에 필요한 기본 메타데이터를 검색한다.

사용자 인터페이스는 단일 검색어를 중심으로 구성하고, 외부 API의 구체적인 검색 조건은 Adapter에서 처리한다.

국립중앙도서관 ISBN 서지정보 API의 실제 호출과 응답 구조 확인을 완료했지만, 검색 결과 품질과 이용 조건 검증은 아직 남아 있다.

따라서 국립중앙도서관을 우선 실험 대상으로 유지하되 최종 공급자로 확정하지 않는다.

초기 구현에서는 하나의 외부 API만 연동하고, 복수 공급자 연동이나 캐싱은 필요성이 확인된 후 고려한다.

도서 메타데이터의 저장 방식은 [ADR-011](../decisions/011-user-book-metadata-snapshot.md)에 따른다.
