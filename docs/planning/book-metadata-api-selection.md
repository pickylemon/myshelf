# 도서 메타데이터 API 선정 및 검색 설계

- **작성일:** 2026-10-26
- **최종 수정일:** 2026-11-18
- **상태:** 국립중앙도서관 API 연동·검색·등록 구현 완료 (Feature 5, PR #25). 실제 검색 품질·성능·이용 조건 검증은 후속
- **관련 기능:** Feature 5 — 외부 도서 검색 및 사용자별 도서 관리
- **관련 결정:** [ADR-011 — 사용자별 도서 메타데이터 스냅샷 저장](../decisions/011-user-book-metadata-snapshot.md)

## 1. 목적과 요구사항

MyShelf의 핵심은 도서정보 제공 자체가 아니라 **사용자별 Shelf 구성과 독서 상태 관리**이다. 외부 도서 API는 사용자가 책을 등록하는 데 필요한 정보를 조회하기 위해 사용한다.

### 기능 범위

- 하나의 `keyword`로 제목·저자·출판사를 검색한다.
- 유효한 ISBN을 가진 도서를 등록 대상으로 하며, ISBN과 제목은 필수 정보로 취급한다.
- 검색 결과에 사용자별 등록 여부, 독서 상태, 등록된 Shelf 정보를 함께 보여준다.
- 검색과 등록을 분리한다. **검색만으로는 DB에 저장하지 않는다.**
- 외부 API 장애가 기존 Shelf 조회 및 사용자 도서 검색에 영향을 주지 않도록 한다.
- ISBN 직접 검색, 수동 등록, 외부 상세 페이지 연결은 초기 필수 기능이 아니며 별도로 결정한다.

책소개·목차·서평·가격·페이지 수·세부 판본 정보는 초기 저장 범위에서 제외한다.

### 저장 모델과의 관계

[ADR-011](../decisions/011-user-book-metadata-snapshot.md)에 따라 공통 `Book` 엔티티를 두지 않고 `UserBook`에 최소 메타데이터의 스냅샷을 저장한다.

| 데이터 | 처리 |
|---|---|
| ISBN, 제목, 저자 | 기존 `UserBook` 정보 |
| 출판사, 표지 이미지 URL | V5 및 `UserBookEntity`에 반영 완료 |
| 출판 예정일 | 외부 검색 결과에만 표시, DB에 저장하지 않음 |
| 독서 상태 | `UserBook`에서 사용자별 관리 |
| Shelf 연결 | `ShelfBook`을 통해 관리 |

동일 사용자의 ISBN 중복 등록은 `UNIQUE(user_id, isbn)`으로 방지한다. 하나의 `UserBook`은 여러 Shelf에 연결될 수 있으며, 모든 Shelf에서 제거되어도 `UserBook` 자체는 유지한다. 기존 등록 도서의 메타데이터는 자동 갱신하지 않는다.

> `publisher`, `cover_image_url`은 엔티티와 V5에 정의되어 있다. 마이그레이션 파일의 존재와 각 실행 환경 DB의 실제 적용 상태는 구분한다.

## 2. API 후보 비교 및 선정 근거

| 후보 | 장점 | 한계·확인 사항 | 판단 |
|---|---|---|---|
| **국립중앙도서관 ISBN 서지정보 API** | 국내 ISBN 서지정보, 기본 메타데이터, 공공데이터 이용 조건 확인 가능 | 통합 키워드 검색 부재, 검색 결과 병합 필요, 표지 누락 가능 | **우선 선정** |
| **YES24 Open API** | 통합 키워드 검색, 표지·상품정보가 비교적 풍부함 | 출처 표기·상품 링크 요구, 영구 저장 허용 범위 불명확 | 초기 저장 모델 적용 보류 |
| 카카오 Daum 책 검색 | 키워드 검색 및 도서 메타데이터 지원 | ISBN-10/13 처리, 저장·재사용 약관, 쿼터 확인 | 대안 |
| 도서관 정보나루 | ISBN 기반 상세정보, 도서관 데이터 | 현재 검색 요구와의 적합성, 이용 조건 확인 | 보조 후보 |
| Google Books | 국내외 도서 검색 | 한글 도서 품질, 출판일 정밀도, 저장 조건 확인 | 해외 도서 확장 시 재검토 |

네이버 책 검색 API는 기존 조사에서 2026-07-31 서비스 종료가 확인되어 신규 후보에서 제외했다.

### 선정 기준

1. **필수:** ISBN 정확성, 국내 도서 검색 품질, 기본 메타데이터 제공, 저장·재사용 허용 여부
2. **중요:** 제목·저자·출판사 검색 가능 여부, 페이징·중복 처리 복잡성, 표지 제공률
3. **운영:** 호출 제한, 응답 시간, 장애 처리, 인증 및 연동 편의성

MyShelf는 외부 API 응답을 화면에 일시적으로 보여주는 데 그치지 않고, 사용자 등록 시 기본 정보를 장기간 보존한다. 따라서 **검색 편의성보다 데이터 이용 조건을 우선**하여 국립중앙도서관 API를 먼저 구현한다.

이는 구현을 위한 우선 선정이며, **메타데이터 장기 저장 조건과 표지 이미지 표시 권리는 최종 확인이 필요하다.** 공공데이터의 이용 조건과 개별 이미지의 권리는 구분한다. 검증 완료 후 최종 선정 근거를 ADR로 남길지 결정한다.

### YES24 비교에서 확인한 점

- 검색 API는 단일 `query`로 도서를 조회할 수 있고, 종이책 검색에는 `category=BOOK`을 활용할 수 있다.
- 응답에 ISBN-13, 제목, 저자, 출판사, 표지 URL, 상품 링크, `publishDate` 등이 포함된다.
- 실제 응답의 `publishDate`는 `yyyyMMdd` 형식이었다. 미래 출간 예정 도서에도 값이 존재하므로 실제 발행일이라고 단정할 수 없다.
- 비교한 ISBN 샘플 2건에서 YES24의 `publishDate`와 국립중앙도서관의 `PUBLISH_PREDATE`가 일치했다. 이는 제한된 샘플 결과다.
- 제공받은 YES24 이용약관에는 API 데이터 표시 시 **YES24 출처와 상품 페이지 링크 제공 의무**가 있고, 성능 목적의 임시 캐싱과 별도의 장기 데이터 축적은 구분되어 있다. 사용자별 최소 메타데이터 영구 저장 가능 여부는 확인되지 않았다.

## 3. 국립중앙도서관 API 실제 검증

### 요청·응답

2026-10-29에 아래 조건으로 ISBN 서지정보 API의 JSON 응답을 확인했다. 인증키는 기록하지 않는다.

```text
GET /seoji/SearchApi.do
result_style=json
page_no=1
page_size=2
title=제과
```

응답에서 `TOTAL_COUNT="1297"`, `PAGE_NO="1"`, `docs` 2건을 확인했다.

```json
{
  "TOTAL_COUNT": "1297",
  "PAGE_NO": "1",
  "docs": [
    { "EA_ISBN": "...", "TITLE": "..." }
  ]
}
```

### 매핑 필드와 주의사항

| 필드 | 의미·처리 |
|---|---|
| `TOTAL_COUNT`, `PAGE_NO` | 문자열로 제공. **검색 조건별** 외부 페이지 진행 상태에 사용 |
| `docs` | 도서 목록. 필요 없는 필드는 역직렬화 시 무시 |
| `EA_ISBN` | ISBN. 중복 제거·등록의 기준 |
| `TITLE` | 제목. 등록 필수 |
| `AUTHOR` | 저자. `저자 :` 등 접두 표현 및 빈 값 주의 |
| `PUBLISHER` | 출판사. 누락 가능 |
| `TITLE_URL` | 표지 **이미지** URL. 비어 있을 수 있음 |
| `PUBLISH_PREDATE` | 출판사가 신고한 출판 **예정일**, `yyyyMMdd` 또는 빈 값 |
| `BOOK_INTRODUCTION`, `BOOK_TB_CNT`, `BOOK_SUMMARY` | 일부 도서에만 존재하는 상세정보. 초기에는 저장하지 않음 |

- 실험에서 표지 URL과 상세정보는 일부 도서에만 존재했다. 제공률을 일반화할 수는 없다.
- `PUBLISH_PREDATE`는 실제 발행일과 다를 수 있다. `LocalDate`로 변환하되 누락·잘못된 형식을 처리하고, 화면에 출판 예정일 기준임을 안내한다.
- ISBN 검색에는 우절단 검색 특성이 있어, 특정 ISBN을 조회할 경우 응답의 ISBN과 요청값을 별도로 대조해야 한다.
- `@JsonIgnoreProperties(ignoreUnknown = true)`는 최상위 응답 DTO와 내부 도서 응답 DTO에 각각 적용한다.

### 복합 조건 검색 실험

`title`과 `author`를 함께 전달한 요청이 0건을 반환하는 등, 복합 조건은 **AND 방식으로 동작하는 것으로 관찰**했다. 다만 공식적인 결합 규칙을 확정한 것은 아니며, 파라미터 무시 가능성까지 완전히 배제한 테스트도 아니다.

따라서 MyShelf의 OR 성격 통합 검색은 **세 조건을 각각 요청한 뒤 애플리케이션에서 병합**하는 방식으로 구현한다.

## 4. 검색 구조 및 책임 분리

국립중앙도서관 전용 요청·응답 변환과 필드별 결과 병합은 외부 Adapter에서 처리한다. Application Service는 검색 진행과 사용자별 등록정보 결합을 담당한다. 외부 전용 DTO를 Application의 Port에 노출하지 않는다.

현재 구성 요소와 데이터 흐름은 [검색 아키텍처의 책임 경계](../architecture/book-search.md#책임-경계)를 참고한다. 현재 응답에는 등록 서재 목록을 포함하며, 독서 상태 결합은 후속 범위다.

API Key의 실제 값은 환경변수로 관리한다. 외부 API의 필드명·응답 형식은 이 문서의 [실제 검증 결과](#3-국립중앙도서관-api-실제-검증)에 남긴다.

## 5. 검색 페이징 및 상태 관리

외부 API 페이지와 사용자에게 반환할 페이지를 분리하고, 남은 도서와 필드별 조회 위치를 서버에 보관하는 **상태 유지형 검색**을 채택했다.

- 대안 비교·상태 구성·선택 근거: [ADR-012](../decisions/012-stateful-book-search-pagination.md#검토한-대안)
- 다음 결과의 가능성을 나타내는 `hasNext`: [ADR의 정책과 트레이드오프](../decisions/012-stateful-book-search-pagination.md#hasnext-정책)
- 현재 요청 흐름·페이지 크기·조회 상한: [검색 아키텍처](../architecture/book-search.md#페이징종료-정책)
- 저장소 선택과 만료 설정: [현재 구현 상태](../architecture/book-search.md#현재-구현-상태)

### 남은 검색 품질 검증

- 제목·저자·출판사 결과의 병합 순서와 정렬 일관성
- 중복이 많을 때 빈 결과가 반환되는 빈도와 사용자 경험
- 외부 API 결과 순서가 검색 도중 변할 경우의 누락·중복 가능성
- 실제 사용량에 따른 검색 상태 저장 비용과 만료 안내 방식

## 6. 검증 계획과 미결정 사항

### 검색 품질 검증

대표 도서 약 10권을 대상으로 국내 일반서·IT 서적·번역서·구간·신간·개정판·절판 도서 등을 비교한다.

- 제목·저자·출판사 키워드 검색 성공 여부
- ISBN 정확성 및 ISBN-10/ISBN-13 정규화 필요성
- 저자·출판사·표지 누락률과 실제 이미지 접근 가능 여부
- 출판 예정일의 형식·누락·미래 날짜 처리
- API 응답시간, 호출 제한 및 이용 조건

### 예외·페이징 검증

계층별 테스트 구성과 검증 방법은 [도서 검색 테스트 전략](../learning/testing/book-search-testing-strategy.md#1-무엇을-실제로-연결할-것인가)에서 관리한다. 실제 외부 API의 응답시간·호출 제한·검색 품질은 Mock 기반 테스트와 별도로 확인한다.

## 7. 현재 결론

국립중앙도서관 ISBN 서지정보 API를 **우선 연동 대상으로 선정**한다. 통합 검색을 위해 제목·저자·출판사를 개별 호출하고, ISBN으로 중복을 제거한 뒤 사용자 등록정보와 결합한다.

검색 ID와 Redis 상태 저장을 구현하고 계층별 테스트를 추가했다. `hasNext`는 추가 결과의 가능성으로 취급한다. 실제 외부 API의 성능·허용량, 저장소 운영 및 사용자 안내 방식은 후속 검증 대상으로 남긴다.
